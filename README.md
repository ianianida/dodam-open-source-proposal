# 도담도담 — 오픈소스 프로젝트 제안

임산부가 온라인 쇼핑 중 자신에게 해당하는 식품 주의사항을 확인하도록 돕는 프로젝트를 제안한다. 상품 정보를 다른 AI 앱으로 옮기고 질문하는 수고를 줄이는 것이 목표다.

현재는 **개별 프로젝트 제안 단계**다. 이 자료에는 설계와 개발 계획이 담겨 있으며, 실행 가능한 구현 코드와 성능 검증 결과는 아직 없다.

## 분석·개선 대상

[Open Food Facts Python SDK](https://github.com/openfoodfacts/openfoodfacts-python)를 분석·개선 대상으로 삼는다. 원본 SDK는 식품 정보를 조회하고 검색하는 기능을 제공한다. 본 제안에서는 이 조회 결과에 사용자 조건별 주의사항, 적용 이유, 출처와 정보 누락 상태를 연결하는 기능을 추가한다.

| 구분 | 원본의 기능 | 추가할 기능 |
| --- | --- | --- |
| 상품 확인 | 상품 조회·검색 | 쇼핑 상품과 조회 후보의 일치 여부 확인 |
| 반환 정보 | 상품의 식품 정보 | 사용자에게 해당하는 안내와 적용 이유 |
| 설명 근거 | 조회된 상품 정보 | 안내 기준별 출처 연결 |
| 정보 누락 | 조회 결과를 호출 측에서 해석 | 누락 항목과 추가로 확인할 조건 표시 |

위 표는 개선 계획이며 구현 완료 내역이 아니다. 원본을 fork한 뒤 조회 함수와 반환 구조를 확인하고 변경할 위치를 정한다.

## 핵심 범위

- 임신 주차·건강 조건·알레르기를 반영하되, 근거가 있는 조건에만 안내를 적용한다.
- 주의사항, 적용 이유, 출처와 추가 확인 조건을 함께 보여준다.
- 상품을 식별하지 못하거나 정보가 부족하면 확인 필요 상태를 반환한다.
- AI는 상품 정보를 구조화하고 채택된 근거를 읽기 쉬운 설명으로 정리하는 데 사용한다.
- 시연 환경은 PC 쇼핑 페이지 한 곳과 예시 상품으로 구성한다. 지원할 쇼핑몰은 데이터 접근 가능성을 확인한 뒤 정한다.

## 시스템 구성

![상품 정보와 사용자 조건을 연결하는 구조](02_시스템개요.png)

브라우저 확장 프로그램의 요청을 Python API 서버가 받아 SDK 확장 기능을 실행하고 결과를 반환한다. 그림은 기능의 관계를 보여주는 설계안이다.

## 개발·검증 계획

1. 원본 저장소를 fork하고 조회·검색 코드, 반환 구조와 라이선스를 확인한다.
2. 선택한 쇼핑 상품의 정보가 데이터에 있는지 먼저 확인한다. 상품명만으로 같은 상품이라고 확정하지 않고 브랜드·규격·성분을 함께 대조한다.
3. 검토한 안내 기준과 사용자 조건을 연결해 결과를 반환한다. 정보 누락과 지원하지 않는 조건을 함께 처리한다.
4. Python API 서버와 쇼핑 화면의 확인 버튼·결과 패널을 연결한다.
5. 안내 기준이 안정된 뒤 AI의 정보 추출·설명 기능을 연동한다.
6. 예시 상품 10~15개와 가상 프로필로 안내·출처의 연결, 정보 누락, 상품 오인과 지원하지 않는 조건을 검증한다.
7. 원본 조회 결과와 추가 안내 결과를 비교한다. 별도 앱을 거치는 방식과 시제품의 화면 전환·입력 횟수, 확인 시간도 비교한다.

팀 주제로 선정되면 4명이 원본 코드·데이터 분석, 안내 기능, 화면 연동, 검증·문서화를 나누고 서로의 변경을 리뷰한다.

## 라이선스와 자료 이용

원본 Python SDK의 MIT 라이선스 고지를 유지한다. 식품 데이터는 코드와 별도로 Open Food Facts의 ODbL 및 해당 자료의 재사용 조건을 확인한다. 현재 제출 자료에는 원본 코드나 식품 데이터 사본을 포함하지 않았다. 구현 시에는 코드와 데이터의 고지 및 출처를 각각 기록한다.

- [원본 SDK와 라이선스](https://github.com/openfoodfacts/openfoodfacts-python)
- [Open Food Facts API와 데이터 이용 안내](https://openfoodfacts.github.io/openfoodfacts-server/api/)
- 식품·임신 관련 안내 자료는 [제안서의 출처](proposal.md#7-출처)에 정리했다.
